# ISP Follow-up, Escalation, and Restoration Email Templates

This guide provides reusable email formats for following up with an ISP after reporting a link issue. Use only the template that matches the current incident status.

> **Confidentiality:** This is a public learning repository. Do not commit real circuit IDs, customer/site details, internal IP addresses, ISP ticket numbers, screenshots, or other confidential operational information. Use actual incident details only in approved company systems.

---

## 1. ISP Follow-up Email

**Subject:** Follow-up: [P2P/ILL] [Bandwidth] Mbps Link Issue — ISP Ref [Reference Number]

Dear [ISP] Team,

We are following up on the reported [Link Down/Link Flapping] issue affecting our [P2P/ILL] [Bandwidth] Mbps link at [Location].

**ISP Ticket/Reference Number:** [Reference Number]  
**Circuit ID:** [Circuit ID]

Kindly share the current status of the investigation and the expected time of restoration (ETR).

Request you to prioritize the issue and keep us updated on further progress.

## 6. Before Sending Checklist

- [ ] Check the latest monitoring status before stating whether the issue is still down or restored.
- [ ] Use the correct ISP ticket/reference number.
- [ ] Verify the circuit ID and link type in the approved internal system.
- [ ] Include the previous ETR only if it was actually provided.
- [ ] State impact factually; do not exaggerate.
- [ ] Follow the organization's escalation and communication process.
- [ ] Never claim restoration until it has been verified.
- [ ] Keep confidential production details out of public documentation.

## Key Takeaways

- Follow up using the existing ISP reference number when available.
- If the ETR is exceeded, request an updated status and revised ETR.
- Escalate according to the organization's process.
- An ISP restoration message is not a substitute for internal verification.
- Keep all communication concise, factual, and professional.
